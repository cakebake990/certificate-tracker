# UX Design Principles

- **Add is fast.** Ask only for information needed to establish a useful certificate record.
- **Update is guided.** Help staff remember context-dependent operational steps during renewal or replacement.
- **One primary question per wizard screen.** Keep decisions clear and reduce cognitive load.
- **Conditional prompts appear only when applicable.** Do not burden every user with every possible scenario.
- **Use plain operational language.** Prefer familiar terms and actionable instructions over technical or policy jargon.
- **Avoid blame-oriented language.** Describe state, risk, and next actions without attributing fault.
- **Support owns expiration work as a team.** The experience should reinforce shared visibility and responsibility.
- **Use retro DOS visual language with modern accessibility.** Aim for “1992 appearance, 2026 usability” through original visual primitives, semantic HTML, keyboard and mouse support, responsive behavior, visible focus, contrast, labels, and assistive-technology compatibility.
- **Back navigation preserves entered values.** Moving through a wizard must not punish review or correction.
- **Review before committing important changes.** Present a clear summary and consequences before persistence.

Color must never be the only status cue. Function-key styling is a visual/action convention, not a substitute for discoverable controls or standard browser behavior.
